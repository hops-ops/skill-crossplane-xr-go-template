# Crossplane Platform Setup & Router

Single entry point for all Crossplane XRD work. Loads platform configuration, runs setup if needed, and routes to the appropriate workflow.

## Step 1: Load Configuration

Check for `hops-crossplane.yaml` in the current project root (the working directory).

```bash
ls hops-crossplane.yaml
```

- **If the file exists** — read it and go to Step 4 (Show Summary).
- **If the file does not exist** — go to Step 2 (Setup Interview).

## Step 2: Setup Interview

Ask the user for their platform settings using AskUserQuestion. Gather all of the following:

1. **GitHub organization** — e.g., `my-org`
2. **API group domain** — e.g., `platform.mycompany.io` (also used as the label prefix)
3. **Container registry** — e.g., `ghcr.io/my-org/`
4. **Kubernetes API version** for XRDs — e.g., `v1alpha1`
5. **Crossplane provider preferences** — which cloud providers? (AWS, GCP, Azure, or a combination)

## Step 3: Write Configuration

Write the gathered values to `hops-crossplane.yaml` in the project root:

```yaml
# Hops Crossplane Platform Configuration
# Generated by /hops-crossplane

github:
  org: <github-org>

platform:
  apiGroup: <api-group-domain>
  labelPrefix: <api-group-domain>/
  registry: <container-registry>
  apiVersion: <api-version>

providers:
  - <provider-1>
```

Tell the user this file should be checked into version control so the whole team shares it.

## Step 4: Show Summary

Display the current platform configuration:

```
Platform Configuration (hops-crossplane.yaml)
----------------------------------------------
GitHub org:      <org>
API group:       <apiGroup>
Label prefix:    <labelPrefix>
Registry:        <registry>
API version:     <apiVersion>
Providers:       <providers, comma-separated>
```

## Step 5: Route

Ask the user what they want to do using AskUserQuestion with these options:

| Option | Action |
|--------|--------|
| **Author a new Composite Resource** | Delegate to `/hops-xr-new` |
| **Audit an existing XRD** | Delegate to `/hops-xr-audit` |
| **Validate & test** | Delegate to `/hops-xr-validate` |
| **Run completion checklist** | Delegate to `/hops-xr-checklist` |
| **Simplify templates** | Delegate to `/hops-xr-got-simplify` |
| **Reconfigure platform settings** | Go back to Step 2 |

When delegating to a sub-command, first remind Claude of the platform config values from `hops-crossplane.yaml`. The sub-commands and agents should use these concrete values instead of the default placeholders in `hops-xr-core` (like `platform.example.com`, `<your-org>`, etc.).

## How Config Values Flow

Before invoking any sub-command, read `hops-crossplane.yaml` and use the values to replace defaults:

| Config field | Replaces placeholder |
|---|---|
| `github.org` | `<your-org>`, `my-org` |
| `platform.apiGroup` | `platform.example.com` |
| `platform.labelPrefix` | `platform.example.com/` |
| `platform.registry` | `ghcr.io/<your-org>/` |
| `platform.apiVersion` | `v1alpha1` (often already the default) |
| `providers` | Provider list passed to template structure and patterns agents |
